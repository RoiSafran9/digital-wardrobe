# 360 "On Body" Turn View — Design

## Context

Owners want to see a garment from every side. Research (stores' 360 apparel, AI ghost-mannequin tools) and a
spike on a real closet item led here:

- Users photograph only front and back (sometimes sides), never a walk-around video, so photogrammetry is out.
- Flat-lay images have no volume; a 360 of a flat shirt says little. Stores show apparel in 360 as a
  **ghost mannequin** (garment worn by an invisible body).
- Spike: the existing image model (`gemini-2.5-flash-image`) rendered 4 ghost-mannequin angles (0° front,
  90° right, 180° back, 270° left) from the flat front/back catalog images in ~50s total (~$0.16). Volume and
  color were convincing. Known weaknesses: a back print was dropped, the front print flipped sides, a mannequin
  neck showed in profiles. **The owner accepted this quality as-is** for the first version.

## Decisions

- **Optional and explicit:** a "View in 360" action on an item; never automatic (it costs ~16¢ and ~1 min).
- **Views:** 4 generated ghost-mannequin angles — front, right, back, left — in that turn order.
- **Generation:** front first from the flat front (+ back when the item has one), then right/back/left with the
  generated front as an anchor for volume and proportions (the spike's method and prompt).
- **Cutouts:** each view goes through the existing local cutout (`pipeline/stages/cutout.py`, interior-filled), so
  views float like every other garment.
- **Async job:** the server starts generation in the background and returns at once; the app polls status. No
  request stays open ~60s.
- **Honesty:** the 360 is labelled "AI view" in the UI, because the angles are generated, not photographed.
- **No new paid services:** same Gemini key; no 3D models, no Replicate/fal.

## Backend

- `pipeline/turn.py`: `run_turn(front_path, back_path | None, out_dir, providers, logger) -> list[str]`
  - generates `front`, `right`, `back`, `left` PNGs in `out_dir`, then cutouts (`<view>_cutout.png`);
  - raises `TurnFailed(message)` on generation failure.
- Provider: `ImageGenProvider.generate_view(refs: list[tuple[str, bytes]], view: str) -> bytes` (Gemini
  implementation uses the spike prompt, kept in `pipeline/prompts/turn_view_v1.txt`).
- Storage: `runs/<run>/<photo>/<item>/turn/` with the 4 images, their cutouts, and `status.json`
  `{ "state": "running" | "done" | "failed", "error": string | null, "started_at": iso }`.
- API:
  - `POST /items/{run}/{photo}/{item}/turn` → `202 {state: "running"}`; starts a background task. If a job is
    already running → `409`. If the item has no generated front → `404`.
  - `GET /items/{run}/{photo}/{item}/turn` → `{state, error, views: [{angle, url, cutout_url}] }`.
  - Closet items gain `turn: {state, views} | null`.
  - Images served at `/images/{run}/{photo}/{item}/turn/{file}` (allow-list: the 8 view files).
- A job interrupted by a server restart (status `running` older than 5 min) reports `failed` with
  "Interrupted — try again".

## App

- **Item sheet:**
  - no turn yet → a "View in 360" button under the image with the cost/time note ("about a minute");
  - running → the staged processing status ("Dressing the invisible mannequin…" → "Turning it around…" →
    "Cutting it out…"), polling every 2s; the sheet can be closed and reopened while it runs;
  - done → the main image becomes the **TurnView** with a small "360 · AI view" label;
  - failed → the error and a "Try again" button.
- **TurnView** (`src/components/TurnView.tsx`): takes an ordered list of N views.
  - Horizontal drag scrubs continuously around the circle: the two neighbouring views crossfade by drag
    progress (one view per ~90pt of drag), wrapping past the last back to the first; release snaps to the
    nearest view with a spring; tap advances one view.
  - Dots show the current view; VoiceOver: adjustable element ("Front", "Right side", "Back", "Left side") with
    increment/decrement actions.
  - Reduce Motion: no scrub crossfade — tap/swipe switches views with a short fade.
  - Works for N = 2 (front/back photos) too, so a photo-only turn can reuse it later.
- **Closet grid:** items with a finished 360 show a small "360" badge on the tile.

## Testing

- `pipeline/turn.py` with a fake provider: 4 views in order, front anchors the others, back reference used when
  present and skipped when absent, cutouts written, failure raises `TurnFailed`.
- API: start → 202 and status running; second start while running → 409; done status lists 4 views with URLs;
  missing item → 404; stale running job reports failed; image route serves only allow-listed files.
- App: TurnView shows first view, tap advances and wraps, drag past half a step snaps to next, accessibility
  actions, Reduce Motion path; item sheet states (button / running with polling / done shows TurnView and label /
  failed with retry); client calls for start and status.

## Out of scope

- Fixing print fidelity across angles (accepted as-is for v1; revisit with prompt work or a better model).
- Side photos, photo-only turn UI entry point, 3D models, video capture.
